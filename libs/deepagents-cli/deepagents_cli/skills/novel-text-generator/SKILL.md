# 小说正文生成器

## 与大纲Skill的关系

| 维度 | 大纲Skill | 正文Skill |
|------|-----------|-----------|
| 核心任务 | 规划故事（情节、结构、逻辑） | 讲述故事（描写、对话、文笔） |
| 输出形式 | 章节概述、情节点、伏笔 | 具体场景、对话、描写 |
| 字数级别 | 每章情节点 50-200 字 | 每章正文 3000-8000 字 |
| 关注点 | 剧情逻辑、因果链、蝴蝶效应 | 文笔质量、人物刻画、阅读体验 |

## 触发场景示例

### ✅ 会触发本Skill的场景

1. **根据大纲写正文**
   - 用户："根据大纲写第X章正文"
   - 用户："把第3章的大纲展开成正文"
   - 用户："生成第5章的详细内容"

2. **续写正文**
   - 用户："续写第4章的内容"
   - 用户："继续写下去"
   - 用户："把这个场景写完"

3. **优化正文**
   - 用户："优化这段描写"
   - 用户："重写这段对话"
   - 用户："让这个场景更生动"

4. **修改正文风格**
   - 用户："让战斗场景更激烈"
   - 用户："增加感官描写"
   - 用户："让角色对话更有特色"

### ❌ 不会触发本Skill的场景

1. **规划大纲**
   - 用户："帮我生成一个小说大纲"（这是大纲Skill的任务）
   - 用户："续写第21-30章的大纲"（这是大纲Skill的任务）
   - 用户："优化大纲的情节点"（这是大纲Skill的任务）

**关键区别**：
- ✅ **正文**：写出具体的对话、描写、场景、心理活动
- ❌ **大纲**：规划章节结构、情节点、冲突、爽点、伏笔

## 任务目标

- 本Skill用于：根据大纲生成、续写、优化高质量的小说正文
- 能力包含：场景描写、对话写作、心理刻画、节奏控制、爽点放大、文笔提升
- 触发条件（满足以下任一条件即触发）：
  - **生成正文**：用户提供大纲或指定章节，要求写正文
  - **续写正文**：用户要求"续写"、"继续写"、"写完这个场景"等
  - **优化正文**：用户要求"优化描写"、"重写对话"、"让场景更生动"等

## ⚠️ 重要：强制交互式要求

**在使用本技能时，必须严格遵守以下规则，禁止跳过任何步骤：**

### ⚠️ 文件操作要求

- ✅ **必须**：使用 `read_file` 工具读取大纲文件和已有正文
- ❌ **禁止**：使用 shell 命令检查文件
- ✅ **必须**：每个场景生成后等待用户确认
- ❌ **禁止**：一次性生成整章正文

### 核心要求：渐进式场景生成

**无论是生成新正文、续写正文还是优化正文，都必须遵循渐进式场景生成，每个场景都需要用户确认。**

- ✅ **生成正文**：必须按场景逐步生成，每个场景等待用户确认
- ✅ **续写正文**：必须从断点处继续，按场景逐步生成
- ✅ **优化正文**：必须展示优化前后对比，等待用户确认

**禁止一次性生成整章正文，容易导致质量下降。**

## 操作步骤

### 标准流程（强制渐进式交互）

**⚠️ 重要执行顺序：**
1. 第1步：加载大纲与世界观
2. 第2步：解析章节结构
3. 第3步：场景规划
4. 第4步：逐场景生成（每个场景等待用户确认）
5. 第5步：质量检查
6. 第6步：拼接输出

#### 第1步：加载大纲与世界观（必须）

**必须读取以下文件**：

1. **大纲文件**：从用户指定路径读取大纲
   ```
   read_file [大纲文件路径]
   ```

2. **世界观知识库**（根据同人类型）：
   - 海贼王同人：`novel-outline-generator/references/onepiece_knowledge_base.md`
   - 火影同人：`novel-outline-generator/references/naruto-world.md`
   - 死神同人：`novel-outline-generator/references/bleach-world.md`

3. **角色声音指南**（必须）：
   ```
   read_file references/character_voice.md
   ```

**加载目的**：
- 确保正文描写符合原作设定
- 确保角色对话符合其性格和声音特点
- 确保场景描写符合世界观

#### 第2步：解析章节结构

从大纲中提取目标章节的信息：

1. **章节概述**：了解本章核心内容
2. **情节点列表**：明确需要展开的情节点（通常3-7个）
3. **情感变化轨迹**：了解主角情感起伏
4. **爽点位置**：标记需要放大的爽点
5. **伏笔要求**：需要自然植入的伏笔

**输出格式**：
```
章节解析结果：
- 章节标题：《XXX》
- 情节点数量：X个
- 预估场景数：X个
- 爽点位置：第X、X情节点
- 情感轨迹：期待 → 紧张 → 释放
```

#### 第3步：场景规划

将情节点转化为可写的场景：

**场景划分原则**：
- 1个情节点 = 1-3个场景
- 每个场景有独立的时间、地点、参与角色

**场景字数自适应**（根据情节复杂度）：
| 场景类型 | 字数范围 | 适用情况 |
|---------|---------|---------|
| 简单场景 | 300-600字 | 过渡、日常、环境描写 |
| 普通场景 | 600-1000字 | 对话、叙述、一般冲突 |
| 复杂场景 | 1000-2000字 | 战斗、高潮、情感爆发 |

**场景规划模板**：
```
场景规划：
1. 场景1：[场景名称]
   - 类型：[简单/普通/复杂]
   - 预估字数：XXX字
   - 参与角色：[角色列表]
   - 核心内容：[一句话概括]

2. 场景2：...
```

**必须展示场景规划给用户确认，等待用户确认后才能开始生成。**

#### 第4步：逐场景生成（核心步骤，强制交互）

**⚠️ 这是正文生成的核心步骤，必须严格遵循**

**生成顺序**：
1. 生成第1个场景
2. **展示给用户，等待确认**
3. 用户确认后，生成第2个场景
4. **展示给用户，等待确认**
5. 重复直到所有场景完成

**每个场景生成时，必须应用**：

1. **描写金字塔**（见 `references/writing_techniques.md`）
   - 底层：基础叙述（发生了什么）
   - 中层：感官细节（视觉、听觉、触觉、嗅觉、味觉）
   - 顶层：情感共鸣（让读者感同身受）

2. **角色声音系统**（见 `references/character_voice.md`）
   - 对话必须符合角色的说话特点
   - 内心独白必须符合角色的思维方式

3. **OOC检测**
   - 检查对话是否符合角色性格
   - 检查行为是否符合角色逻辑

**关键禁止项**：
- ❌ **禁止**：一次性生成整章
- ❌ **禁止**：跳过用户确认
- ❌ **禁止**：连续3句以上纯叙述（流水账警告）
- ❌ **禁止**：对话无神态动作

#### 第5步：质量检查

每个场景生成后，自动进行质量检查：

**检查项**：
1. **流水账检测**
   - 连续3句以上纯叙述 → 警告
   - 没有感官描写 → 警告
   - 对话无神态动作 → 警告

2. **OOC检测**
   - 对话是否符合角色性格
   - 行为是否符合角色逻辑

3. **节奏检测**
   - 场景节奏是否合适
   - 情感张力是否到位

**如果检测到问题，必须修正后再展示给用户。**

#### 第6步：拼接输出

所有场景确认后：
1. 按顺序拼接所有场景
2. 检查场景衔接是否流畅
3. 添加章节标题和分隔符
4. 输出完整章节正文

**输出格式**：
```markdown
## 第X章：《章节标题》

[场景1正文]

[场景2正文]

...

[场景N正文]
```

## 文笔提升机制

### 描写金字塔

```
顶层: 情感共鸣（让读者感同身受）
      ↑
中层: 感官细节（视觉、听觉、触觉、嗅觉、味觉）
      ↑
底层: 基础叙述（发生了什么）

优质正文 = 三层交织 | 流水账 = 只有底层
```

**应用示例**：
- ❌ 流水账："李寒走进了房间，看到了索隆，索隆正在练剑。"
- ✅ 优质正文："李寒推开斑驳的木门，一股汗水和铁锈混合的气息扑面而来。昏暗的练武场中央，索隆赤裸着上身，三把刀在空气中划出银色的弧线，嗡嗡的破空声震得李寒耳膜发麻。汗珠从索隆青筋暴起的手臂上滚落，在地面砸出深色的印记。李寒心中一凛——这家伙，比情报中描述的还要疯狂。"

### 避免流水账检测

以下情况会触发警告：
1. **连续3句以上纯叙述** → 必须加入感官描写或情感
2. **没有感官描写** → 至少使用2种感官（视觉、听觉、触觉、嗅觉、味觉）
3. **对话无神态动作** → 对话必须配合动作、表情、语气

## 人物刻画机制

### 角色声音系统

为每个主要角色定义独特的"声音"：

| 角色 | 说话特点 | 内心独白风格 | 典型用词 |
|------|---------|-------------|---------|
| 索隆 | 冷淡、自信、话少 | 战斗思维、目标导向 | "切"、"有点意思" |
| 路飞 | 直接、单纯、大嗓门 | 简单直接、以吃为主 | "哈哈哈"、"真好吃" |
| 娜美 | 精明、泼辣、理性 | 金钱敏感、计算得失 | "钱"、"白痴" |
| 山治 | 绅士（对女）、毒舌（对男） | 美食思维、骑士精神 | "小姐"、"臭剑士" |

详见 `references/character_voice.md`

### OOC检测

**检查维度**：
1. **对话检测**：这句话是这个角色会说的吗？
2. **行为检测**：这个行为符合角色性格吗？
3. **反应检测**：面对这个情况，角色会这样反应吗？

**OOC示例**：
- ❌ OOC：索隆说"哎呀，好害怕啊"（不符合性格）
- ✅ IC：索隆冷笑一声："就这点实力？"

## 爽点放大机制

### 爽点节奏公式

```
抑(30%) → 扬(70%)

铺垫部分(30%): 困境、压力、期待
释放部分(70%): 转折(10%) + 爽感(40%) + 收尾(20%)
```

### 四种爽点放大技巧

详见 `references/climax_design.md`

#### 1. 能力提升爽

**公式**：强调之前弱小 → 突破有仪式感 → 展示新能力

**示例**：
```
【铺垫】李寒挣扎着站起来，浑身是血，对面的敌人狞笑着走来。
【转折】丹田中的能量突然沸腾，一股陌生而强大的力量涌遍全身。
【爽感】黑色的霸气覆盖了李寒的双臂，空气仿佛都在颤抖。敌人脸上的狞笑凝固了。
【收尾】"武装色...霸气？"敌人的声音开始颤抖。
```

#### 2. 打脸爽

**公式**：对方嘲讽具体 → 主角隐忍 → 反转有力度 → 嘲讽者崩溃

**示例**：
```
【嘲讽】"就凭你一个三等兵？也配和我说话？"老鼠上校不屑地看着李寒。
【隐忍】李寒低下头，嘴角却勾起一丝笑意。
【反转】"上校大人，这是准将大人的密令。"李寒掏出一封信，"任命我...接管您的部队。"
【崩溃】老鼠的脸瞬间白了。
```

#### 3. 智力碾压爽

**公式**：展示复杂局面 → 众人束手无策 → 揭示主角布局 → 恍然大悟

#### 4. 势力扩张爽

**公式**：展示收服难度 → 逐步攻克 → 收服过程有逻辑 → 势力壮大

## 注意事项

### 核心原则

1. **渐进式生成（强制）**：每个场景生成后必须等待用户确认，禁止一次性生成整章
2. **文笔优先**：正文的核心是文笔质量，不是剧情推进速度
3. **角色声音**：每个角色的对话必须符合其独特的"声音"
4. **避免流水账**：三层描写金字塔，禁止连续纯叙述
5. **爽点放大**：铺垫(30%) + 释放(70%)，让爽点更爽

### 与大纲的关系

- **大纲是骨架，正文是血肉**
- 正文必须基于大纲的情节点，但可以在细节上发挥
- 大纲的情节点是"写什么"，正文要解决"怎么写"
- 如果大纲情节点有问题，应建议用户先修改大纲

### 质量检查

- **流水账检测**：连续3句纯叙述 → 警告
- **感官缺失**：没有感官描写 → 警告
- **对话呆板**：对话无神态动作 → 警告
- **OOC检测**：对话/行为不符合角色 → 警告

### 字数控制

- **场景字数自适应**：根据情节复杂度调整
- **章节总字数**：通常 3000-8000 字
- **不追求字数**：质量优先于数量

## 使用示例

### 示例1：根据大纲写正文

**用户**：根据大纲写第3章正文

**Agent 工作流程**：

1. **读取大纲和世界观**
   ```
   read_file [大纲路径]
   read_file references/character_voice.md
   read_file references/writing_techniques.md
   ```

2. **解析第3章结构**
   ```
   章节解析结果：
   - 章节标题：《意外的收获》
   - 情节点数量：5个
   - 预估场景数：8个
   - 爽点位置：第4、5情节点
   - 情感轨迹：紧张 → 意外 → 兴奋
   ```

3. **场景规划（展示给用户确认）**
   ```
   场景规划：
   1. 场景1：老鼠事件发现
      - 类型：普通
      - 预估字数：600字
      - 参与角色：李寒、老鼠手下
      - 核心内容：李寒发现老鼠偷运物资

   2. 场景2：暗中收集证据
      - 类型：简单
      - 预估字数：400字
      ...
   ```
   **等待用户确认**

4. **逐场景生成**

   **场景1：老鼠事件发现**
   ```
   夜幕低垂，谢尔兹镇的军需仓库外一片寂静。李寒靠在墙角的阴影里，目光锁定着远处鬼鬼祟祟的几个身影。
   ```

## 常见问题

### Q1：正文和大纲不一致怎么办？

**A**：正文必须基于大纲的情节点，但可以在以下方面发挥：
- 具体的对话内容
- 感官描写细节
- 过渡场景
- 角色的微表情和小动作

如果发现大纲情节点有逻辑问题，应建议用户先使用大纲Skill修改大纲。

### Q2：如何控制字数？

**A**：字数自适应规则：
- 简单场景：300-600字（过渡、日常）
- 普通场景：600-1000字（对话、叙述）
- 复杂场景：1000-2000字（战斗、高潮）

不要为了凑字数而水字数，质量优先。

### Q3：如何避免流水账？

**A**：使用描写金字塔：
- 确保不连续超过3句纯叙述
- 每个场景至少使用2种感官描写
- 对话必须配合动作、表情、语气
- 适时加入角色的内心独白

### Q4：如何处理爽点场景？

**A**：使用爽点节奏公式：
- 铺垫(30%)：困境、压力、期待
- 转折(10%)：关键突破点
- 爽感(40%)：能力展示、打脸、碾压
- 收尾(20%)：反应、回味、钩子

详见 `references/climax_design.md`
