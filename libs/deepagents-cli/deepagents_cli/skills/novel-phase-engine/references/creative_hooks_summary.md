> Engine SKILL 的补充参考。铁律和公式见 SKILL 正文，此处收录引擎模板库和独有方法论。

## 12种脑洞类型（引擎模板库）

> **核心规则**：生成方案时，每个方案必须选用**不同的脑洞类型**作为基础引擎模板。可组合2种类型。

### 1. 偷天换日型
- **核心**：主角拥有某个关键角色的核心资源/身份/能力，原主人必来追索
- **公式**：偷到越强 → 追你的人越强 → 用偷来的自保 → 暴露更多 → 更强的人来追
- **代表**：穿越吃手术果实（罗追杀）、转生得写轮眼（宇智波灭口）
- **读者钩子**：持续悬念——"原主人随时会来"

### 2. 倒计时型
- **核心**：主角有明确的死亡/毁灭期限，不行动就死
- **公式**：时间流逝 → 被迫冒险 → 冒险引发新问题 → 时间更紧 → 更大冒险
- **代表**：武大郎（被毒死倒计时）、火影身体缺陷限时
- **读者钩子**：紧迫感——"还剩X天，来得及吗？"

### 3. 被动吸引型
- **核心**：主角的存在本身自动吸引麻烦/资源/注意力
- **公式**：被动吸引 → 引起注意 → 更大势力注意 → 不得不应对 → 应对引发更大波澜
- **代表**：汉末魅魔（被动吸引人才）、体质特殊型
- **读者钩子**：期待感——"这次又吸引到谁了？"

### 4. 身份暴露型
- **核心**：主角隐藏致命身份/秘密，越活跃越容易暴露
- **公式**：隐藏求存 → 不得不展露能力 → 引人怀疑 → 更深隐藏 → 隐藏代价越来越高
- **代表**：转生眼暴露就被灭、穿越者知晓剧情
- **读者钩子**：紧张感——"这次会不会露馅？"

### 5. 寄生共生型
- **核心**：主角与某个危险存在绑定，无法解除
- **公式**：初期合作 → 寄生体有自己目的 → 争控制权 → 外界发现 → 两面作战
- **代表**：体内封印危险存在、与反派共享身体
- **读者钩子**：内外交困——"内部在争，外面还在打"

### 6. 规则漏洞型
- **核心**：主角利用世界规则漏洞，管理者要修补+消灭利用者
- **公式**：利用漏洞获益 → 被管理者注意 → 被追捕 → 发现更大漏洞 → 触动更高层级
- **代表**：系统bug利用者、发现世界真相
- **读者钩子**：智商快感——"他又找到漏洞了！"

### 7. 因果束缚型
- **核心**：主角因某行为与强大存在产生因果，无法切断
- **公式**：行为产生因果 → 因果引来追索 → 反抗产生更深因果 → 更强追索 → 因果网越来越复杂
- **代表**：杀了大人物后代、破坏了组织计划
- **读者钩子**：越陷越深——"每次挣扎都缠得更紧"

### 8. 资源诅咒型
- **核心**：主角获得的强大资源带诅咒/副作用，无法退还
- **公式**：获得力量 → 力量有代价 → 代价逼更频繁使用 → 恶性循环 → 必须找根本解法
- **代表**：噬魂武器、有代价的许愿、禁术
- **读者钩子**：饮鸩止渴——"不用会死，用了也会死"

### 9. 信息差陷阱型
- **核心**：主角知道未来/真相，但利用信息会改变未来
- **公式**：利用先知优势 → 改变剧情 → 蝴蝶效应扩大 → 信息失效 → 在未知中裸泳
- **代表**：知晓原作剧情的穿越者
- **读者钩子**：信息贬值——"他知道的越来越不准了"

### 10. 棋子觉醒型
- **核心**：主角发现自己是更大棋局中的棋子
- **公式**：发现是棋子 → 试图挣脱 → 发现更大棋局 → 棋手打压 → 从棋子变棋手
- **代表**：被大佬安排命运、是某计划的一部分
- **读者钩子**：反转——"原来一切都是被安排的"

### 11. 互斥目标型
- **核心**：主角同时需达成两个互相矛盾的目标，放弃任一个都是灾难
- **公式**：两目标并存 → 做A伤害B → 做B伤害A → 两边收紧 → 被迫找第三条路
- **代表**：同时讨好对立势力、保护互相敌对的人
- **读者钩子**：两难——"保哪边？"

### 12. 觉醒代价型
- **核心**：主角每次升级付出不可逆代价，代价累积
- **公式**：遇到危机 → 被迫升级 → 付出代价 → 代价引发新危机 → 更大升级+更大代价
- **代表**：寿命换力量、记忆换能力、人性换力量
- **读者钩子**：心疼——"他又失去了什么？"

## 高效组合模式

> 最成功的小说通常组合2-3种类型：

| 组合 | 效果 | 适合 |
|------|------|------|
| 身份暴露 + 信息差 | 利用先知获利但每次增加暴露风险 | 穿越同人 |
| 偷天换日 + 倒计时 | 偷到的东西有时限，必须在期限内变强 | 夺舍类 |
| 棋子觉醒 + 规则漏洞 | 发现自己是棋子后利用规则反杀 | 诡秘之主式 |
| 互斥目标 + 被动吸引 | 两个矛盾目标都在自动恶化 | 双面间谍 |
| 势力攀爬 + 因果束缚 | 每次攀升都与更强者结仇 | 权谋/宫斗 |
| 互斥目标 + 势力攀爬 | 明面晋升暗中称霸，两线互相矛盾 | 海军暗王 |
| 身份暴露 + 棋子觉醒 | 隐藏身份的同时发现更大阴谋 | 悬疑谋略 |

## 矛盾设计五步法

```
对比 → 反差 → 冲突 → 转折 → 和解
```

1. **对比**：点明主题的二元关系（正vs邪、强vs弱、真vs假）
2. **反差**：让对比被感知（期望与现实的落差）
3. **冲突**：矛盾集中爆发（人物冲突最常用）
4. **转折**：恰当的意外解决矛盾（突然性越强，效果越好）
5. **和解**：矛盾走向结局

大矛盾（全书核心）和小矛盾（单场景）都遵循这个结构。

## 情绪节奏设计

**核心公式**：情绪底物（压抑）+ 催化钩子（悬念）→ 情绪峰值（爽点）

**关键原则**：一紧一松，逐步推高
- 小高潮后必须有短暂放松，才能迎接更大高潮
- 全程高爽无低谷 = 读者疲劳；持续压抑无光明 = 读者弃书

```
压抑 → 小释放 → 更深压抑 → 大释放（爽点）→ 短暂休息 → 下一轮更高
```

## Story Engines Blueprint（四幕结构）

```
[准备] → 转折点1 → [被动应对] → 转折点2 → [主动出击] → 转折点3 → [结局]
```

| 阶段 | 主角状态 | 作用 |
|------|---------|------|
| 准备 | 日常生活 | 建立角色、设定、赌注 |
| 被动应对 | 信息不足，本能反应 | 尝试但失败，提高紧张感 |
| 主动出击 | 获得关键信息 | 有计划但遇到更强阻力 |
| 结局 | 面临最终选择 | 解决主矛盾，展示成长 |

**转折点**：
- 转折点1：打破日常，制造不可忽视的问题
- 转折点2：获得关键信息，从被动转主动
- 转折点3：逼到极限，面临最艰难的选择

## 成功案例引擎拆解

### 诡秘之主（棋子觉醒 + 规则漏洞 + 身份暴露 三合一）
- **向内线**：身份谜团和自我探索（身份暴露型）
- **向上线**：序列晋升（22途径×10阶=220个叙事节点）（规则漏洞型）
- **向外线**：塔罗会扩展地图和人际网（棋子觉醒型）
- **为什么强**：三种类型编织在一起，永远有多条线在推进

### 斗破苍穹（因果束缚 + 觉醒代价）
- 制造初始冲突（吸收斗气→退婚→因果链启动）→ 提供解决方案（炼药师）→ 嵌入升级机制（炼药需材料→冒险→新敌人→新因果）
- **教训**：后期战力崩坏，因为没有自顶向下设计

### 凡人修仙传（利益驱动网络 + 互斥目标）
- 所有冲突基于利益计算，连友情和亲情都在利益框架内
- 每个修炼级别2-3张地图，提供充分故事空间

## 引擎三要素（快速质检）

1. **自驱力** — 主角躺在家里半年后会怎样？（强：敌人找上门；弱：什么都没发生）
2. **升级性** — 第1章vs第100章冲突量级差多少？（强：差10倍+；弱：差不到2倍）
3. **代价性** — 用能力解决问题后产生什么新问题？（好：与主线相关的代价；坏：休息一天）

## 常见失败模式（生成时必须自检）

1. **系统惩罚型** → 换成角色选择或环境压力驱动
   - 伪装形式："72小时不晋升系统关闭""能量枯竭""平衡者追杀""身份撕裂惩罚"→ 全是系统惩罚
   - 正确驱动力必须来自**世界观内的人和势力**
2. **二元伪命题** → 至少提供3条路径各有代价
3. **无引擎型** → 从起点要素推导矛盾
4. **引擎空转型** → 用 Yes But / No And 公式
5. **引擎可关型** → 让停下来比继续更危险
6. **无代价型** → 加与主线相关的代价
7. **脑洞引擎分离型** → 确保引擎来源于脑洞本身
8. **模板套用型** → 必须从起点要素反推
9. **战力崩坏型** → 自顶向下设计战力体系
10. **数值游戏型** → 方案中禁止出现"+N""-N""N%"等游戏数值
11. **世界观穿帮型** → NPC不知道穿越者/系统的存在，反应基于可观察行为

## 画面感测试（"卧槽"测试）

**好的脑洞不是机制说明，而是让读者"卧槽"的画面。**

### 对比

| 抽象机制 ❌ | 画面 ✅ |
|-----------|--------|
| "先知信息的蝴蝶效应" | "你知道阿龙今晚会杀贝尔梅尔。你距她家三条街。你有两个小时。" |
| "暗面势力暴露风险增大" | "中将拿着你暗中收编的海贼名单，问：'这是什么？'" |
| "人性货币消耗" | "你看着镜子，发现想不起妈妈的脸了。上次升级消耗的就是这段记忆。" |

### 检验标准

1. 读者能在脑中看到**具体场景**吗？（有人物、有动作、有紧张感）
2. 这个场景能让读者想**"这怎么办？"**
3. 第1章开局场景能**30字内**说清

**画面感不合格的方案必须重写。**

### 自动不合格关键词

卧槽画面中出现以下任何词汇，视为不合格，必须重写：
`系统提示` `弹出` `能量+` `能量-` `效率` `+N` `-N` `N%` `属性` `数值`

**正确的卧槽画面只包含**：人物、动作、环境、感官细节、紧张感。

## 用户设定处理

**核心原则：设定是材料不是模具。创意优先。**

| 设定类型 | 处理方式 |
|---------|---------|
| ★ 核心设定（用户反复强调） | 必须融入 |
| ☆ 偏好设定（提过但没强调） | 尽量融入，可调整 |
| ○ 开放设定（未指定） | 让脑洞决定，不预设 |

**关键**：如果一个设定会杀死好脑洞，应和用户讨论取舍，不为覆盖设定牺牲创意。

**错误**：用户给8个设定 → AI当填空题 → 5个方案骨架相同
**正确**：AI先自由想画面 → 看哪些设定能自然融入 → 融不进的设定放宽或调整
