# 创意脑洞 + 引擎方法论

## 概览

成功网文的脑洞不是一次性的开局设定，而是贯穿全书的**"创意引擎"**——它持续驱动冲突升级，从第1章到最后一章。脑洞是种子，引擎是种子的生长机制。**两者必须一起设计，不可分割。**

---

## A. 不可逃避性四问检验

**每个脑洞+引擎方案必须全部通过以下四个检验，缺一不可：**

### 四问清单

| # | 检验问题 | 通过标准 | 失败示例 |
|---|---------|---------|---------|
| 1 | 主角能选择"不管"吗？ | **不能**。结构性地无法逃避，不是不愿意，是不可能。 | ❌ "主角可以选择不用金手指" → 那读者为什么要看？ |
| 2 | 冲突会自动找上门吗？ | **是**。不需要主角主动作死，困境会自己来。 | ❌ "主角需要主动去挑衅才有冲突" → 引擎没有自驱力 |
| 3 | 困境会升级吗？ | **是**。解决A必然产生B，B比A更难。 | ❌ "每次都是同级别的挑战" → 引擎没有升级性 |
| 4 | 优势有代价吗？ | **是**。用金手指/能力解决问题，会产生新的更大问题。 | ❌ "金手指无副作用" → 没有代价的爽文 |

### 检验示例

**通过的例子**：「穿越后吃了手术果实，但罗要杀你」
1. 能不管吗？→ 不能，果实已吃，罗一定会来
2. 冲突自动来？→ 是，罗在主动追踪
3. 会升级？→ 是，从罗个人→到更大势力→到四皇
4. 有代价？→ 是，用果实=暴露位置

**失败的例子**：「穿越获得加点系统」
1. 能不管吗？→ 能，不加点也能活 ❌
2. 冲突自动来？→ 不会，需要主角去找事 ❌
3. → 检验未通过，需要重新设计引擎

## B. 12种脑洞类型

### 类型1：偷天换日型
- **核心机制**：主角拥有了某个关键角色的核心资源/身份/能力
- **不可逃避性来源**：原主人一定会来讨要/复仇
- **引擎生长方式**：原主人的追索力度不断升级，涉及的势力越来越大
- **代表作**：穿越吃了手术果实（罗来追杀）、转生得到写轮眼（宇智波要灭口）
- **引擎公式**：偷到的东西越强 → 追你的人越强 → 用偷来的东西自保 → 暴露更多 → 更强的人来追

### 类型2：倒计时型
- **核心机制**：主角有一个明确的死亡/毁灭期限
- **不可逃避性来源**：时间不等人，不行动就死
- **引擎生长方式**：倒计时压力下被迫做出越来越冒险的选择
- **代表作**：武大郎（知道要被毒死的倒计时）、火影（身体有缺陷的限时）
- **引擎公式**：时间在流逝 → 被迫冒险 → 冒险引发新问题 → 时间更紧 → 更大的冒险

### 类型3：被动吸引型
- **核心机制**：主角的存在本身就会吸引麻烦/资源/注意力
- **不可逃避性来源**：不是主角想不想的问题，是他的体质/血统/身份自动吸引
- **引擎生长方式**：吸引的范围从局部扩展到全局
- **代表作**：汉末魅魔（被动吸引人才/异性）、体质特殊型
- **引擎公式**：被动吸引 → 引起注意 → 更大势力注意 → 不得不应对 → 应对引发更大波澜

### 类型4：身份暴露型
- **核心机制**：主角隐藏着一个一旦暴露就致命的身份/秘密
- **不可逃避性来源**：越活跃越容易暴露，但不活跃就会被淘汰
- **引擎生长方式**：暴露风险随能力提升而增大
- **代表作**：转生眼（暴露转生者身份就被灭）、穿越者知晓剧情
- **引擎公式**：隐藏身份求存 → 不得不展露能力 → 引人怀疑 → 更深入隐藏 → 隐藏的代价越来越高

### 类型5：寄生共生型
- **核心机制**：主角与某个危险的存在绑定，共生或寄生
- **不可逃避性来源**：绑定无法解除，必须共存
- **引擎生长方式**：寄生体的需求不断升级，从合作到控制之争
- **代表作**：体内封印着某个危险存在、与反派共享身体
- **引擎公式**：初期合作 → 寄生体有自己的目的 → 主角与寄生体争控制权 → 外界发现寄生体 → 两面作战

### 类型6：规则漏洞型
- **核心机制**：主角发现/利用了世界规则的漏洞
- **不可逃避性来源**：漏洞被发现后，世界/管理者会来修补，顺带消灭利用者
- **引擎生长方式**：从小漏洞到大漏洞，触动的利益越来越大
- **代表作**：系统bug利用者、发现世界真相
- **引擎公式**：利用漏洞获益 → 被系统/管理者注意 → 被追捕 → 发现更大漏洞 → 触动更高层级

### 类型7：因果束缚型
- **核心机制**：主角因为某个行为/选择，与某个强大存在产生了因果关系
- **不可逃避性来源**：因果关系无法切断，对方一定会来清算
- **引擎生长方式**：因果的连锁反应不断扩大
- **代表作**：杀了某个大人物的后代、破坏了某个组织的计划
- **引擎公式**：行为产生因果 → 因果引来追索 → 反抗产生更深因果 → 更强的追索 → 因果网越来越复杂

### 类型8：资源诅咒型
- **核心机制**：主角获得的强大资源本身带有诅咒/副作用
- **不可逃避性来源**：资源已经使用/融合，无法退还
- **引擎生长方式**：副作用随使用次数/强度递增
- **代表作**：噬魂型武器、有代价的许愿、禁术
- **引擎公式**：获得强大力量 → 力量有代价 → 代价逼迫更频繁使用 → 恶性循环 → 必须找到根本解法

### 类型9：信息差陷阱型
- **核心机制**：主角知道未来/真相，但利用信息的行为本身会改变未来
- **不可逃避性来源**：蝴蝶效应使信息越来越不准确，但已经依赖信息行动
- **引擎生长方式**：从小蝴蝶效应到完全偏离原剧情
- **代表作**：知晓原作剧情的穿越者
- **引擎公式**：利用先知优势 → 改变剧情 → 蝴蝶效应扩大 → 信息失效 → 在未知中裸泳

### 类型10：棋子觉醒型
- **核心机制**：主角发现自己是某个更大棋局中的棋子
- **不可逃避性来源**：棋手不会放弃棋子，要么被用到死，要么反抗被灭
- **引擎生长方式**：从发现棋局到对抗棋手
- **代表作**：被某个大佬安排了命运、是某个计划的一部分
- **引擎公式**：发现自己是棋子 → 试图挣脱 → 发现更大棋局 → 棋手打压 → 从棋子变棋手

### 类型11：互斥目标型
- **核心机制**：主角同时需要达成两个互相矛盾的目标
- **不可逃避性来源**：两个目标都是生存必须，放弃任一个都会死
- **引擎生长方式**：两个目标的冲突越来越尖锐
- **代表作**：需要同时讨好两个对立势力、保护两个互相敌对的人
- **引擎公式**：两个目标并存 → 做A伤害B → 做B伤害A → 两边都在收紧 → 被迫找第三条路

### 类型12：觉醒代价型
- **核心机制**：主角的能力每次觉醒/升级都会付出不可逆的代价
- **不可逃避性来源**：不升级就打不过面前的敌人，但升级的代价会累积
- **引擎生长方式**：代价从小到大，每次都是"这次不得不付"
- **代表作**：寿命换力量、记忆换能力、人性换力量
- **引擎公式**：遇到危机 → 被迫升级 → 付出代价 → 代价引发新危机 → 更大的升级+更大的代价

## C. 脑洞+引擎一体化生成公式

### 标准模板

每个方案必须同时包含脑洞和引擎，使用以下格式：

```
方案X：「标题（冒号格式：世界观：核心困境）」

脑洞（种子）：
  一句话描述核心设定

引擎（生长机制）：
  核心矛盾：XX与YY不可调和
  驱动力：什么力量在持续推动冲突？
  升级机制：小→中→大→超大，每级的关键转变
  不可停止：为什么主角无法喊停？
  代价：用优势解决问题时要付出什么？

弧线预览（3-5个弧）：
  弧1（开篇）：引擎启动——初始冲突
  弧2（发展）：引擎加速——冲突扩大
  弧3（升级）：引擎过载——更高层级的矛盾
  弧4（高潮）：引擎极限——最终对决
  弧5（终局）：引擎归宿——主题回收

四问检验：
  1. 能不管吗？→ [回答]
  2. 冲突自动来？→ [回答]
  3. 会升级？→ [回答]
  4. 有代价？→ [回答]
```

### 引擎强度对标

生成方案后，必须与已有成功案例对标：
- **自驱力**：和"汉末魅魔"的被动吸引力相比，是否同样自动？
- **升级性**：和"转生眼"的暴露风险升级相比，是否同样递进？
- **不可停止性**：和"武大郎"的倒计时相比，是否同样无解？

如果三项中有任一项明显弱于对标案例，需要重新加强该维度。

## D. 引擎设计三要素

### 1. 自驱力（引擎的启动和持续能力）

引擎必须能**自动运转**，不依赖主角"作死"来制造冲突。

- **强自驱力**：罗主动追踪你（你什么都不做，他也会找到你）
- **中自驱力**：系统发布任务逼你行动（有外力推动）
- **弱自驱力**：主角需要主动去找事（需要"作死"才有冲突）❌

**检测方法**：如果主角躺在家里不动，半年后会怎样？
- 强引擎：半年后敌人找上门
- 弱引擎：半年后什么都没发生 → 引擎失败

### 2. 升级性（引擎的递进能力）

引擎产生的冲突必须**持续升级**，不能一直在同一个层面转圈。

**升级路径模板**：
```
个人（1-30章）→ 组织（31-80章）→ 势力（81-150章）→ 天下（151+章）

示例：
罗追杀你 → 罗加入某势力追杀你 → 势力战争中你成为关键棋子 → 四皇级别的争夺
```

**检测方法**：第1章的冲突和第100章的冲突，量级差多少？
- 强引擎：差10倍以上（个人恩怨→天下大势）
- 弱引擎：差不到2倍 → 引擎升级性不足

### 3. 代价性（引擎的反噬能力）

使用优势/金手指解决问题时，必须**产生新的更大问题**。

**代价链模板**：
```
用能力A解决问题1 → 产生副作用B → 副作用B变成问题2 → 用能力A+解决问题2 → 产生更大副作用C
```

**好的代价设计**：
- 每次用果实能力 → 暴露位置信号 → 被追踪
- 每次用系统升级 → 消耗寿命 → 倒计时缩短
- 每次改变原剧情 → 蝴蝶效应扩大 → 先知优势减弱

**坏的代价设计**：
- 用完能力需要休息一天 → 不影响剧情走向 ❌
- 每次消耗一些金币 → 金币可以刷 ❌

## E. 常见失败模式（反面教材）

### 失败模式1：无引擎型
- **症状**：有脑洞但没有持续冲突，开局有趣后面无聊
- **典型表现**：穿越获得系统，然后就是打怪升级打怪升级...
- **为什么失败**：系统本身不制造冲突，它只是工具。工具不会追杀你。
- **修复方法**：给系统加入引擎——比如系统有自己的目的，完不成任务会惩罚/杀死宿主

### 失败模式2：引擎空转型
- **症状**：有引擎但冲突不升级，100章了还在打小喽啰
- **典型表现**：同样级别的敌人换了一批又一批
- **为什么失败**：引擎没有升级机制，冲突在同一层面循环
- **修复方法**：设计明确的升级路径（个人→组织→势力→天下），每30-50章必须上一个台阶

### 失败模式3：引擎可关型
- **症状**：主角可以选择退出冲突，但他"选择"不退出
- **典型表现**："明明可以跑路，但主角就是要留下来打"
- **为什么失败**：不可逃避性是假的，读者会问"为什么不跑"
- **修复方法**：让退出的代价比留下更大，或者结构性地无法退出（果实已吃、身份已暴露、倒计时在走）

### 失败模式4：无代价型
- **症状**：主角使用能力没有任何副作用，一路碾压
- **典型表现**：金手指越用越强，没有任何限制
- **为什么失败**：没有代价就没有张力，没有张力就不好看
- **修复方法**：每次使用都产生可见的、与主线相关的代价（不是"休息一天"这种无关紧要的代价）

### 失败模式5：脑洞引擎分离型
- **症状**：脑洞很有趣，但引擎和脑洞是两码事
- **典型表现**：开局设定很酷，但后续冲突和开局设定无关
- **为什么失败**：脑洞只在前几章起作用，后面就被遗忘了
- **修复方法**：确保引擎的冲突**来源于脑洞本身**——是因为你吃了果实才被追杀，不是因为别的什么事

## F. 画面感测试（"卧槽"测试）

**核心原则：好的脑洞不是一段机制说明，而是一个让读者"卧槽"的画面。**

### 为什么需要画面感

AI生成脑洞时最常见的问题是产出**游戏设计文档而不是故事**：
```
❌ 机制说明（读者无感）：
"每用一次先知信息，未来剧情偏离10%，100章后原作剧情完全失效"
"每晋升一级军衔，暗中势力暴露风险+20%"
"军衔晋升需要消耗人性货币——记忆、情感、道德感"

✅ 画面描述（读者心跳加速）：
"你穿越成武大郎，潘金莲端着一碗汤走过来，你知道里面有毒。"
"曹操看你的眼神越来越不对劲，他叫侍卫关上了门。"
"宗家长老掰开你的眼皮检查，你拼命压制查克拉波动。"
```

### 画面感检验（每个方案必须通过）

| # | 检验项 | 通过标准 | 失败示例 |
|---|-------|---------|---------|
| 1 | 读者能在脑中看到一个具体场景吗？ | 有人物、有动作、有紧张感 | ❌ "蝴蝶效应让剧情偏离" |
| 2 | 这个场景能让读者想"这怎么办？" | 困境是具体的、可视化的 | ❌ "暴露风险+20%" |
| 3 | 第1章的开局场景能一句话说清吗？ | 30字内描述一个画面 | ❌ "主角获得系统然后..." |

### 画面感改造示例

| 抽象机制（❌） | 改造为画面（✅） |
|-------------|--------------|
| "先知信息的蝴蝶效应" | "你知道阿龙今晚会杀贝尔梅尔。你距她家三条街。你有两个小时。" |
| "暗面势力暴露风险增大" | "中将坐在你对面，手里拿着一份你暗中收编的海贼名单，问：'这是什么？'" |
| "人性货币消耗" | "你看着镜子，发现想不起妈妈的脸了。上次升级消耗的就是这段记忆。" |
| "双面身份走钢丝" | "革命军的联络人在左边咖啡馆等你，海军情报部的长官在右边路口朝你走来。" |

### 在方案模板中的应用

每个方案除了标准格式外，必须额外包含：
```
卧槽画面（第1章核心场景，30字内）：
  "你刚吃完果实，罗的海贼旗出现在港口。"

开局3章画面流：
  第1章：[一个画面]
  第2章：[一个画面]
  第3章：[一个画面]
```

## G. 用户设定：参考而非硬性约束

**核心原则：好脑洞从创意出发，设定是材料不是模具。**

### 错误做法：设定先行，创意填空

```
用户给了8个设定 → AI把8个设定当填空题 → 找一个"引擎"串联填空
结果：5个方案骨架相同，只换了引擎外衣
```

### 正确做法：创意先行，设定融入

```
AI先自由想出5个让人"卧槽"的画面 → 看哪些用户设定能自然融入 → 融不进去的设定放宽或调整
结果：5个方案各有独特的核心画面和引擎
```

### 设定处理规则

| 设定类型 | 处理方式 | 示例 |
|---------|---------|------|
| 核心设定（用户反复强调的） | 必须融入 | "必须是海贼王世界" |
| 偏好设定（用户提过但没强调） | 尽量融入，可调整 | "最好有收势力的元素" |
| 可推导设定（从脑洞自然长出来的） | 让脑洞决定，不预设 | 主角性格、金手指类型 |
| 冲突设定（与好创意矛盾的） | 与用户讨论取舍 | "统一世界"可能限制引擎空间 |

**关键**：如果一个设定会杀死一个好脑洞，应该和用户讨论是否调整设定，而不是为了覆盖设定牺牲创意。

## 使用指南

### 在脑洞生成阶段

1. 从12种类型中选择1-2种作为基础
2. **先想画面，再想机制**——每个方案先写出"卧槽画面"，再设计引擎
3. 用四问检验每个方案
4. 用画面感测试检验——是画面还是说明书？
5. 用引擎三要素评估强度
6. 与成功案例对标
7. 检查是否存在5种失败模式

### 生成多个方案时

- 至少生成3个方案，让用户选择
- 每个方案应使用不同的脑洞类型（避免同质化）
- **每个方案的核心画面必须完全不同**——不能是同一个骨架换外衣
- 每个方案都必须通过四问检验 + 画面感测试
- 如果用户不满意，可以组合不同方案的元素
- **设定是参考，不是硬性约束**——创意优先

### 与后续步骤的衔接

- 选定的方案直接写入 `engine.md`
- 弧线预览直接指导后续的弧线规划
- 引擎的升级机制决定大纲的长线走向
- 每批章节生成后，用四问重新检验引擎是否还在运转
