## 整体结构

小说大纲必须按照以下结构组织：

```
小说基础信息
├── 小说名称
├── 世界观
├── 主角金手指
├── 主角性格类型
├── 故事线模式
├── 原创程度
├── 风格定位
├── 预计篇幅
└── 更新频率

系统设定（如有）
└── 系统功能描述

主角角色卡
├── 基本信息
├── 力量属性
├── 特殊能力
├── 性格深度
└── 背景故事

故事线结构
├── 第一卷概述
│   ├── 卷概述
│   └── 第1-20章详细大纲
├── 第二卷概述
│   ├── 卷概述
│   └── 第21-40章详细大纲
└── ...
```

## 卷概述规范

每卷必须包含以下字段：

```markdown
### 第X卷：《卷名》

#### 卷概述
**核心主题**: 一句话概括本卷的核心
**核心冲突**: 本卷的主要矛盾
**主角目标**: 3-5个具体目标
**本卷收获**: 本卷的主要收获
**关键事件**: 3-5个关键事件，用→连接
```

## 章节概述规范

每章必须包含以下字段：

```markdown
### 第X章：《章节名》

**章节概述**: 100-200字，概括本章的核心内容

**情节点**:
1. 【小标题】具体描述
2. 【小标题】具体描述
...

**情感变化**: A→B→C（用→连接，展示主角情感变化）

**爽点**: 具体爽点1+具体爽点2

**钩子**: 引发读者好奇的问题

**伏笔**:
- 伏笔1
- 伏笔2
...
```

## 情节点规范

### 基本要求

1. **具体化原则**：每个情节点必须具体，不能模糊
   - ❌ 错误："主角获得力量"
   - ✅ 正确："主角通过拜师学习，获得剑术（入门），然后用系统加点到熟练"

2. **逻辑性原则**：每个情节点必须符合逻辑
   - ❌ 错误："主角凭借个人魅力收服强敌"
   - ✅ 正确："主角展示实力，提供价值，对方考虑后加入"

3. **有迹可循原则**：每个情节点都必须有迹可循
   - ❌ 错误："主角意外发现系统"
   - ✅ 正确："主角在放松状态下发现脑海中有系统界面"

### 情节点的标准格式

每个情节点必须包含【小标题】和具体描述：

```markdown
【小标题】具体描述，包含人物、动作、结果
```

### 不同类型情节点的写作规范

#### 1. 冲突类情节点
- 必须明确冲突双方、冲突原因、冲突过程、冲突结果
- 示例：
  ```markdown
  【克洛船长的阴谋】克洛船长派手下（赞高和布奇）毒杀可雅。可雅喝下毒酒，即将死亡。乌索普冲进来，大喊："可雅！不要喝！"但已经晚了
  ```

#### 2. 获得类情节点
- 必须明确获得途径、获得内容、获得过程
- 示例：
  ```markdown
  【获得剑术】李寒每天往返谢尔兹镇和霜月村，训练剑术。一个月后，获得剑术（入门）
  ```

#### 3. 收服类情节点
- 必须明确收服过程、对方的考虑、最终决定
- 示例：
  ```markdown
  【山治的加入】山治考虑，李寒确实很强，而且救了哲普大叔。山治说："我可以加入你，但我要照顾哲普大叔，而且我要找到All Blue。"李寒说："我可以帮你照顾哲普大叔，我也可以帮你找到All Blue。"山治考虑，最终加入李寒
  ```

#### 4. 系统类情节点
- 必须明确系统发现过程、系统功能、能量变化
- 示例：
  ```markdown
  【能量增加】李寒感觉身体有种奇怪的变化，系统界面自动弹出，显示能量上限从10点提升到30点，恢复速度从每天1点提升到每天3点。他恍然大悟——原来军衔晋升能增加能量！这是自然的过渡，不是他提前知道的
  ```

## 辅助元素规范

### 情感变化

- 格式：A→B→C（用→连接）
- 要求：必须展示主角的情感变化轨迹
- 示例：
  ```markdown
  **情感变化**: 编造情报的紧张→老鼠的恐慌（成功引导）→两虎相争的升级→利用机会的兴奋
  ```

### 爽点

- 格式：具体爽点1+具体爽点2
- 要求：必须具体，不能模糊
- 分类：
  - 小爽点：化解危机、获得小成就
  - 中爽点：收服强敌、技能提升
  - 大爽点：晋升军衔、获得强力能力
- 示例：
  ```markdown
  **爽点**: 收服索隆+晋升伍长+能量增加到200点
  ```

### 钩子

- 格式：引发读者好奇的问题
- 要求：每个章节必须有1-2个钩子
- 示例：
  ```markdown
  **钩子**: 李寒如何收服娜美？娜美会加入海军吗？
  ```

### 伏笔

- 格式：
  ```markdown
  **伏笔**:
  - 伏笔1
  - 伏笔2
  ```
- 要求：
  - 每个章节必须有1-3个伏笔
  - 伏笔必须在后续章节中回收
  - 伏笔不能太明显，要有一定的隐蔽性
- 示例：
  ```markdown
  **伏笔**:
  - 娜美的航海术很强，李寒收服她后，可以学习航海术
  - 娜美的痛苦（诺吉米被杀），李寒可以利用这一点收服娜美
  ```

## 质量检查清单

在生成或优化大纲时，必须检查以下项目：

- [ ] 每章都有章节概述
- [ ] 每章都有7个以上的情节点
- [ ] 每个情节点都符合"具体化、逻辑性、有迹可循"原则
- [ ] 每章都有情感变化
- [ ] 每章都有爽点
- [ ] 每章都有钩子
- [ ] 每章都有伏笔
- [ ] 情节点之间逻辑连贯
- [ ] 角色行动符合性格设定
- [ ] 技能获取符合世界观设定
