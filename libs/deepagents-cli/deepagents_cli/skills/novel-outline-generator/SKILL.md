# 小说大纲生成器

## 触发场景示例

### ✅ 会触发本Skill的场景（执行完整流程）

1. **生成新大纲**
   - 用户："帮我生成一个海贼王同人小说大纲"
   - 用户："设计一个海军主角的故事线"

2. **续写大纲**
   - 用户："请根据现在的大纲续写5章"
   - 用户："根据大纲规划第21-30章的内容"
   - 用户："设计后续5章的大纲"

3. **优化大纲**
   - 用户："优化第5-7章的大纲"
   - 用户："调整大纲，让情节更具体"
   - 用户："修改大纲，收服索隆"

4. **改变剧情**
   - 用户："让主角收服索隆"
   - 用户："改变第10章的剧情"
   - 用户："影响路飞的发展"

5. **蝴蝶效应推理**
   - 用户："分析收服索隆的影响"
   - 用户："推演蝴蝶效应"
   - 用户："如果主角收服索隆，路飞会怎样"

### ❌ 不会触发本Skill的场景（写正文，不是写大纲）

1. **续写小说正文**
   - 用户："续写第4章的内容"（这是写正文）
   - 用户："写第X章内容"（这是写正文）

**关键区别**：
- ✅ **大纲**：规划章节结构、情节点、冲突、爽点、伏笔
- ❌ **正文**：写出具体的对话、描写、场景

## 任务目标
- 本Skill用于：生成、续写、优化高质量的小说大纲
- 能力包含：情节设计、角色塑造、逻辑验证、爽点布局、因果链推理、蝴蝶效应分析
- 触发条件（满足以下任一条件即触发）：
  - **生成新大纲**：用户提供小说基础信息（世界观、主角设定、故事线框架等）
  - **续写大纲**：用户要求"续写大纲"、"根据大纲规划后续章节"、"设计第X-Y章大纲"等
  - **优化大纲**：用户要求"优化大纲"、"修改大纲"、"调整大纲"等
  - **改变剧情**：用户要求"收服XXX"、"改变XXX事件"、"影响XXX角色"等
  - **蝴蝶效应推理**：用户要求"分析改变的影响"、"推演蝴蝶效应"、"如果...会怎样"等

**重要说明**：
- ❌ **不触发本Skill**：用户要求"续写小说正文"、"写第X章内容"、"生成正文"等（这是写正文，不是写大纲）
- ✅ **触发本Skill**：用户要求涉及"大纲"、"规划"、"设计"、"改变剧情"、"蝴蝶效应"等

## ⚠️ 重要：强制交互式要求

**在使用本技能时，必须严格遵守以下规则，禁止跳过任何步骤：**

### ⚠️ 文件操作要求（续写大纲时）
- ✅ **必须**：使用 `read_file` 工具读取文件
- ❌ **禁止**：使用 shell 命令检查文件（如 `shell("type ...")`、`shell("wc -l ...")`、`shell("powershell ...")` 等）
- ❌ **禁止**：使用任何 shell 命令来检查文件行数、内容等
- ✅ **必须**：直接使用 `read_file` 工具读取文件内容

### 核心要求：所有场景都必须执行因果链推理

**无论是生成新大纲、续写大纲还是优化大纲，都必须执行因果链推理，分析不同的剧情走向，生成3个分支供用户选择。**

- ✅ **生成新大纲**：必须执行因果链推理，分析故事框架下的不同发展路径
- ✅ **续写大纲**：必须执行因果链推理，分析续写部分的不同剧情走向
- ✅ **优化大纲**：必须执行因果链推理，分析优化的不同方向和策略

**禁止跳过因果链推理，直接生成、续写或优化大纲。**

### 续写大纲的特殊说明
当用户要求续写大纲时，遵循标准流程，但需要注意：

**⚠️ 重要：续写大纲的执行顺序**
1. 第1步：世界观识别（如果已加载可跳过）
2. 第2步：需求收集（从用户输入识别文件路径，读取现有大纲）
3. **第3步：因果链推理（必须执行，生成3个分支供用户选择）**
4. **等待用户选择分支**
5. 第4步：大纲生成（用户选择分支后才能执行）

**续写时的特殊要求**：
- **必须从用户输入中识别文件路径**，使用用户指定的原始小说文件（如 `e:\git\deepagents-book\novels\海贼王之唯我独尊.md`）
- **必须使用 `read_file` 工具读取文件**，禁止使用 shell 命令检查文件
- **禁止使用任何 shell 命令**：包括但不限于 `shell("type ...")`、`shell("wc -l ...")`、`shell("powershell ...")`、`shell("Get-Content ...")` 等
- **如果需要检查文件内容或行数**：直接使用 `read_file` 工具读取文件，不要使用 shell 命令
- **禁止**读取或编辑内存文件（如 `/memory/user/AGENTS.md`）- 这是 agent 的内存文件，用于存储用户偏好，续写大纲时不应编辑
- **禁止**在生成分支之前创建 todo 列表（write_todos）
- **禁止**在生成分支之前开始编写大纲
- **禁止**在生成分支之前规划剧情走向
- **禁止**在用户选择分支之前，执行任何生成或编辑操作
- 续写时，第2步（需求收集）可以简化，直接根据用户原始需求确定续写范围
- 续写时，第4步（大纲生成）后需要将内容合并到用户指定的原始小说文件

## 续写和优化的记忆机制

### 智能体记忆范围

在续写和优化时，智能体会记住以下信息：

#### 1. **已生成的设定**
- 主角设定：姓名、性格、金手指、背景、初始状态
- 故事框架：主角目标、核心冲突、起点
- 世界观：已加载的世界观知识库（海贼王/火影/死神）
- 蝴蝶效应：已执行的蝴蝶效应推理和用户选择

#### 2. **已生成的剧情**
- 角色状态：当前能力、性格、关系、位置
- 势力状态：当前势力分布、关系
- 伏笔：已埋下的伏笔
- 时间线：当前进度（第几章、第几卷）

#### 3. **用户的偏好**
- 改变偏好：用户喜欢改变哪些原作内容
- 交互偏好：用户喜欢详细的逐步推理还是简洁的分支选择
- 修改偏好：用户经常修改哪些方面（情节、角色、爽点）

### 记忆的作用

1. **减少重复询问**
   - 智能体会记住主角的设定，不会反复询问相同的问题
   - 例如：第一次生成时问"主角的姓名"，续写时不会重复询问

2. **确保连贯性**
   - 智能体会记住已生成的剧情，确保续写内容连贯
   - 例如：主角在第10章获得"武装色霸气"，第21章不会忘记这个设定

3. **支持蝴蝶效应推理**
   - 智能体会记住已执行的蝴蝶效应，推理后续影响
   - 例如：第1章收服索隆，续写第21章时会分析这个改变对后续剧情的影响

4. **保留用户选择**
   - 智能体会记住用户选择的分支，确保续写内容符合用户期望
   - 例如：用户选择"平衡策略"，续写时会延续这个策略

### 记忆的局限性

**智能体不会记住**：
1. **用户的临时想法**：用户提到的但没有确定的想法
2. **未选择的内容**：用户没有选择的分支内容
3. **已放弃的设定**：用户明确放弃的设定

**用户可以主动覆盖记忆**：
- 如果用户希望改变某个设定，智能体会更新记忆
- 例如：用户可以要求"主角的金手指改为加点系统"，智能体会更新记忆

### 续写和优化时的行为

#### 续写时：
1. 智能体会读取现有大纲，提取当前状态
2. 基于记忆中的设定和剧情，生成续写内容
3. 如果用户希望改变某个设定，智能体会更新记忆并执行因果链推理

#### 优化时：
1. 智能体会读取现有大纲，提取当前状态
2. 基于记忆中的设定和剧情，应用8项优化原则
3. 如果优化涉及剧情改变，智能体会执行因果链推理

## 操作步骤（续写和优化的记忆）

### 标准流程（智能体主导，强制对话式交互）

**⚠️ 重要执行顺序：**
1. 第1步：世界观识别与加载
2. 第2步：需求收集
3. **第3步：因果链推理（必须执行，生成3个分支供用户选择）**
4. **等待用户选择分支后**，才能执行第4步
5. 第4步：大纲生成

**关键禁止项（续写大纲时）**：
- ❌ **禁止**：跳过第3步（因果链推理），直接执行第4步（大纲生成）
- ❌ **禁止**：在用户选择分支之前，创建 todo 列表（write_todos）
- ❌ **禁止**：在用户选择分支之前，开始编写大纲
- ❌ **禁止**：在用户选择分支之前，编辑任何文件
- ❌ **禁止**：读取或编辑 `/memory/user/AGENTS.md`（这是 agent 的内存文件，用于存储用户偏好，不是用户指定的文件，续写大纲时不应编辑）
- ❌ **禁止**：直接规划剧情走向，必须先执行因果链推理生成3个分支

#### 第1步：世界观识别与加载（必须）
通过对话识别用户要创作的同人类型，**必须先加载对应的世界观知识库**（只读取一次，后续记住）：

- 海贼王同人：必须读取 `references/onepiece_knowledge_base.md`
- 火影同人：必须读取 `references/naruto-world.md`
- 死神同人：必须读取 `references/bleach-world.md`
- 其他同人：根据具体世界观加载相应文档

**加载目的**：确保 AI 不会胡编乱造，严格遵循原作设定（角色性格、能力体系、剧情逻辑等）

#### 第2步：需求收集（强制对话式）
**必须通过对话逐步从用户处获取信息，禁止一次性推断所有信息**：

- **生成新大纲时**：
  - 主角设定：姓名、性格、金手指、背景、初始状态等
  - 故事框架：主角目标、核心冲突、起点（如"海军"、"海贼"等）
  - 改变需求（如果有）：是否收服原作角色、是否改变原作事件等
  - 章节数量：默认50章/卷，可自定义
- **续写大纲时**：
  - 从用户输入中识别文件路径和续写范围（如"续写接下来的5章"）
  - **必须使用 `read_file` 工具读取现有大纲文件**，提取当前状态
  - **禁止使用 shell 命令检查文件**（如 `shell("type ...")`、`shell("wc -l ...")`、`shell("powershell ...")`、`shell("Get-Content ...")` 等）
  - 根据用户原始需求确定续写范围，无需重复询问

**执行方式**：
1. 每次只问1-2个问题
2. 等待用户回答后，再问下一个问题
3. 禁止一次性推断所有信息并生成大纲
4. **续写时**：禁止在生成分支之前创建 todo 列表或开始编写大纲
5. **续写时**：禁止使用 shell 命令，必须使用 `read_file` 工具

#### 第3步：因果链推理（**强制交互式逐步推理，所有场景都必须执行**）
**⚠️ 重要：无论是生成新大纲、续写大纲还是优化大纲，都必须执行因果链推理，分析不同的剧情走向，生成分支供用户选择。**

**⚠️ 关键：这是续写大纲的核心步骤，禁止跳过！**

**执行顺序（必须严格遵守）**：
1. ✅ **必须**：先执行因果链推理，分析续写部分的不同剧情走向
2. ✅ **必须**：生成3个分支（保守策略/平衡策略/激进策略）
3. ✅ **必须**：展示分支供用户选择，等待用户选择
4. ✅ **必须**：用户选择分支后，才能创建 todo 列表或开始生成大纲

**关键禁止项**：
- ❌ **禁止**：跳过因果链推理，直接创建 todo 列表（write_todos）
- ❌ **禁止**：跳过因果链推理，直接开始编写大纲
- ❌ **禁止**：跳过因果链推理，直接规划剧情走向（如"第4-8章整体规划"）
- ❌ **禁止**：在生成分支之前，创建 todo 列表
- ❌ **禁止**：在用户选择分支之前，开始生成大纲
- ❌ **禁止**：在用户选择分支之前，编辑任何文件（包括 `/memory/user/AGENTS.md`）

**必须执行以下流程，禁止跳过**：

1. **理解需求和分析可能走向**
   - **生成新大纲时**：分析故事框架下的不同发展路径和策略选择
   - **续写大纲时**：分析续写部分的不同剧情走向
   - **优化大纲时**：分析优化部分的不同改进方向
   - **如果有明确的改变需求**（如"收服索隆"）：
     - 询问：您想如何改变？（收服/杀掉/放走）
     - 询问：改变的时机？（哪一章节）
     - 询问：主角的策略是什么？
   - **用户可以补充信息**：用户可以主动提供额外的设定或约束

2. **加载状态**
   - 从知识库加载：原作剧情、角色状态、势力状态、状态依赖

3. **逐步推理（智能体主导，每步都等待用户反馈）**
   - **第1步：分析直接影响**
     - 智能体：分析改变事件对世界的直接影响
     - 等待用户确认或补充
   - **第2步：分析第1层连锁反应**
     - 智能体：分析直接影响相关角色
     - 等待用户确认或补充
   - **第3步：分析第2层连锁反应**
     - 智能体：分析影响后续事件
     - 等待用户确认或补充
   - **第4步：分析第3层连锁反应**
     - 智能体：分析影响长期剧情
     - 等待用户确认或补充
   - **第5步：分析世界修正**
     - 智能体：分析世界如何自动修正剧情
     - 等待用户确认或补充
   - **用户随时可以补充**：
     - 用户可以随时打断推理，补充自己的想法
     - 用户可以要求跳过某些推理步骤
     - 用户可以要求深入分析某个环节

4. **生成3个分支（必须生成，基于用户反馈调整）**
   - 智能体基于推理结果和用户反馈，生成3个分支
   - **生成新大纲时**：
     - 分支A：保守策略（稳步发展，避免风险）
     - 分支B：平衡策略（适度冒险，平衡收益）
     - 分支C：激进策略（大胆行动，高风险高收益）
   - **续写大纲时**：
     - 分支A：保守策略（稳步发展，避免风险）
     - 分支B：平衡策略（适度冒险，平衡收益）
     - 分支C：激进策略（大胆行动，高风险高收益）
   - **优化大纲时**：
     - 分支A：保守优化（最小改动，保持原框架）
     - 分支B：平衡优化（适度改进，平衡改动）
     - 分支C：激进优化（大幅改进，可能改变框架）
   - **如果有明确的改变需求**（如"收服索隆"）：
     - 分支A：保守策略（成功率低，风险小）
     - 分支B：平衡策略（成功率中等，风险中等）
     - 分支C：激进策略（成功率低，风险大）
   - **用户可以修改分支**：用户可以对分支提出修改意见

5. **展示分支供用户选择（必须等待用户选择，禁止自动选择）**
   - 展示每个分支的详细信息：
     - 分支标题
     - 策略类型
     - 详细描述
     - 世界修正信息（修正类型、强度）
     - 蝴蝶效应列表（改变点、连锁反应、长期影响）
     - 成功率分析（百分比、难度等级、原因）
     - 风险分析（风险列表、评估）
     - 收益分析（收益列表、评估）
     - 时间线分析（关键节点、剧情节奏）
     - 一致性校验结果
   - **用户可以补充或修改**：用户可以对分支提出修改意见，或补充自己的方案

6. **等待用户选择分支（禁止自动选择最优分支）**
   - 用户选择：A/B/C/用户自定义
   - 如果用户选择"用户自定义"，智能体基于用户的补充生成新分支
   - 如果用户不满意，可以重新生成分支
   - 如果用户要求深入分析某个分支，智能体展开详细分析

**关键规则**：
- ❌ **禁止**：自动选择最优分支
- ✅ **必须**：逐步推理，每步都等待用户确认或补充
- ✅ **必须**：用户可以随时补充信息
- ✅ **必须**：用户可以修改分支或提供自定义方案
- ✅ **必须**：用户要求深入分析时，智能体展开详细分析
- ❌ **禁止**：跳过用户反馈，直接生成大纲

#### 第4步：大纲生成（智能体主导，**强制渐进式交互**）
**必须先读取**：`references/outline_structure.md` - 了解大纲结构规范

**强制渐进式生成**：
1. 生成卷概述，**展示给用户确认**
2. 用户确认后，生成章节概述，**展示给用户确认**
3. 用户确认后，生成详细情节点（每章至少7个，具体化、有迹可循）
4. 用户确认后，填充辅助元素（情感变化、爽点、钩子、伏笔）

**续写大纲时**：

## 因果链动态推理（核心能力）

当用户提出改变需求时，智能体自动执行因果链推理，支持蝴蝶效应分支生成。

### 推理模式（默认使用交互式逐步推理）

智能体在因果链推理时，**必须使用交互式逐步推理模式**。

#### 模式1：全自动模式（❌ 禁止使用）
- 用户输入需求
- 智能体自动推理、选择最优分支、生成大纲
- **禁止使用场景：用户未明确要求全自动**

#### 模式2：半自动模式（默认推荐）
- 用户输入需求
- 智能体逐步推理，**每步都等待用户确认或补充**
- 基于推理结果和用户反馈，生成3个分支
- 等待用户选择分支（或提供自定义方案）
- **适用场景：大多数情况，用户希望控制剧情走向**

#### 模式3：交互式模式（用于复杂剧情改变）
- 用户输入需求
- 智能体逐步推理，**每步都等待用户确认或补充**
- 用户可以随时打断推理，补充自己的想法
- 用户可以要求跳过某些推理步骤
- 用户可以要求深入分析某个环节
- **适用场景：重大剧情改变、复杂蝴蝶效应**

**关键规则**：
- 默认使用**半自动模式**：逐步推理，每步都等待用户反馈
- **用户可以随时补充信息**：用户可以主动提供额外的设定或约束
- **用户可以修改分支**：用户可以对分支提出修改意见，或提供自定义方案
- **用户可以要求深入分析**：智能体必须展开详细分析
- 禁止使用**全自动模式**：除非用户明确要求"你直接生成"

### 推理流程（半自动模式）

#### 第1步：理解需求
智能体解析用户需求：
- **改变类型**：收服角色/改变事件/影响势力/获得能力
- **改变粒度**：单事件/章节范围/整卷
- **改变对象**：原作角色（路飞、索隆、娜美等）/势力/地点

#### 第2步：加载状态
智能体从知识库加载：
- 原作剧情：相关章节的原作情节
- 世界状态：角色状态（能力、性格、关系）、势力状态、地点状态
- 状态依赖：原作事件触发的前提条件和影响后果

#### 第3步：因果推理
智能体计算：
- **直接影响**：改变事件对世界的直接影响
- **连锁反应**（至少3层）：
  - 第1层：直接影响相关角色
  - 第2层：影响后续事件
  - 第3层：影响长期剧情
- **生成3个分支**：每个分支都是可能的剧情走向

#### 第4步：一致性校验
对每个分支，智能体检查：
- 角色行为是否符合性格？（不能脸谱化）
- 能力获取是否有合理来源？（不能无师自通）
- 势力变化是否有逻辑依据？（不能无脑收服）
- 新情节是否逻辑自洽？（有迹可循）

#### 第5步：分支详细展示
智能体向用户展示3个分支的详细信息，包含以下维度：

**分支基本信息**：
- 分支标题：简要描述分支核心
- 策略类型：保守/平衡/激进
- 详细描述：分支的具体执行方案

**世界修正信息**：
- 修正类型：人物替代/情节补偿/运气加持/角色行为引导
- 修正强度：弱/中/强
- 修正描述：世界如何自动修正剧情

**蝴蝶效应列表**：
- 改变点：主角改变的具体行为
- 连锁反应：改变引发的连锁反应（至少3层）
- 长期影响：对后续剧情的影响

**成功率分析**：
- 成功率百分比：0-100%
- 难度等级：简单/中等/困难/极难
- 成功率原因：基于原作设定、主角实力、机遇等因素分析

**风险分析**：
- 风险列表：详细列出每个分支可能面临的风险
- 风险评估：基于角色性格、世界修正、主角行为等维度评估

**收益分析**：
- 收益列表：详细列出每个分支的潜在收益
- 收益评估：基于战力提升、关系改善、剧情控制等维度评估

**时间线分析**：
- 时间线节点：列出分支的关键时间节点（章节范围）
- 剧情节奏：帮助用户了解分支的剧情节奏

**一致性校验结果**：
- 是否通过一致性校验
- 如果未通过，列出具体问题

用户根据以上信息选择分支（A/B/C）。

#### 第6步：生成大纲
根据用户选择的分支，智能体生成详细大纲：
- 标注改变点
- 标注连锁反应
- 标注蝴蝶效应
- 标注主角vs天意的博弈过程

### 主角行为逻辑原则

在生成分支时，智能体必须遵循以下原则：

#### 1. 对敌人：斩尽杀绝
- 主角对敌人的处理必须是彻底清除
- 不能留后患，不能网开一面

#### 2. 对路人/无冤无仇者：不主动阻挠
- 如果主角已经"偷偷摸摸抢了路飞的机缘"（如收服索隆）
- 那么主角不应该继续阻挠世界修正（如克洛加入路飞）
- 逻辑：已经占了便宜，不贪心

#### 3. 分支的多样性
- 收服不了索隆、收服路飞、收服其他角色，都是可能的分支
- 不应该预设主角一定能成功
- 要根据主角实力和机遇，合理设计成功率

## 优化模式（核心改进点）

当优化现有大纲时，必须遵循以下改进原则：

### 1. 情节具体化
- **原则**：模糊描述必须转化为具体行动
- **示例**：
  - ❌ 错误："李寒获得军功"
  - ✅ 正确："李寒提供老鼠的'内部情报'（实际编造）撬开俘虏的口，蒙卡记一等功"

### 2. 角色逻辑化
- **原则**：角色行动必须符合其性格设定，不能脸谱化
- **示例**：
  - ❌ 错误："老鼠直接派人暗杀李寒"
  - ✅ 正确："老鼠生性多疑阴险，不会直接动手，而是先派人试探李寒是否真的背叛"

### 3. 能量发现自然化
- **原则**：主角获得新发现/能力必须自然过渡，不能开天眼
- **示例**：
  - ❌ 错误："李寒晋升后，主动查看系统，发现能量增加了"
  - ✅ 正确："晋升后，李寒身体自然感到变化，系统界面自动弹出，他这才恍然大悟——原来军衔晋升能增加能量"

### 4. 收服势力合理化
- **原则**：主角收服势力必须有合理依据，不能无脑收服
- **示例**：
  - ❌ 错误："李寒只是小兵，但凭借个人魅力收服了老鼠的残余势力"
  - ✅ 正确："李寒临时负责维持秩序，墙头草士兵看到他已是一等兵且有准将的临时任命，主动投靠"

### 5. 情报明确化
- **原则**：主角提供的情报必须具体，不能模糊
- **示例**：
  - ❌ 错误："李寒编造了关于蒙卡的情报"
  - ✅ 正确："李寒编造'蒙卡已掌握老鼠在橘子镇、西罗布村贪污记录'的情报"

### 6. 战斗过程详细化
- **原则**：两方冲突必须有具体过程，不能省略
- **示例**：
  - ❌ 错误："老鼠和蒙卡两虎相争，双方都重伤"
  - ✅ 正确："老鼠派'假海贼'袭击蒙卡补给船，蒙卡暴怒直接袭击老鼠据点，双方正面冲突，死伤惨重"

### 7. 技能获取常识化
- **原则**：技能获取必须符合世界观，不能无师自通
- **示例**：
  - ❌ 错误："李寒看索隆练剑，学会了他的剑术"
  - ✅ 正确："李寒拜师耕四郎，经过一个月的学习，获得剑术（入门），然后用系统加点到熟练"

### 8. 收服过程逻辑化
- **原则**：收服强敌必须有逻辑过程，不能一蹴而就
- **标准流程**：
  - 派部下观察 → 了解对方需求和困境 → 提供价值（实力、资源、承诺帮助） → 展示实力 → 收服

## 注意事项

- **触发条件**：满足以下任一条件即触发 Skill（生成大纲/续写大纲/优化大纲/改变剧情/蝴蝶效应推理）
- **续写大纲 vs 续写正文**：
  - ✅ **续写大纲**：规划章节结构、情节点、冲突、爽点、伏笔（会触发本Skill）
  - ❌ **续写正文**：写出具体的对话、描写、场景（不会触发本Skill）
  - **关键区别**：大纲是"规划"，正文是"写作"
- **续写和优化必须执行完整流程**：续写和优化时，必须重新执行 Skill 的完整流程（世界观加载、因果链推理、质量检查），确保一致性
- **智能体工具系统**：使用专用工具管理创作状态

  **角色管理（推荐使用专用工具）**：
  - `update_character("索隆", status="已收服", location="东海", note="第5章收服")` - 更新角色状态
  - `get_character("索隆")` - 获取角色详情
  - `list_characters("已收服")` - 列出指定状态的角色
  - `add_relationship("李寒", "索隆", "上下级", mutual=True)` - 添加角色关系

  **伏笔管理（推荐使用专用工具）**：
  - `plant_foreshadow("老鼠交易", "老鼠与海贼有交易", chapter=3, target_chapter=10)` - 埋设伏笔
  - `resolve_foreshadow("老鼠交易", resolved_chapter=10, resolution="揭示真相")` - 回收伏笔
  - `list_foreshadows()` - 查看待回收伏笔

  **大纲完成（强烈推荐）**：
  - `complete_outline(chapter, outline, title?)` - 完成大纲（自动保存+更新进度）

  **进度管理**：
  - `get_progress()` - 查看当前进度
  - `update_progress(outline_completed=10)` - 手动更新进度

  **基础记忆工具（通用）**：
  - `remember("decision", "收服策略", "用户选择平衡策略")` - 记住用户决策
  - `recall("decision")` - 回忆决策信息
  - `forget("decision", "已废弃选择")` - 删除过时信息

- **用户可以覆盖记忆**：如果用户希望改变某个设定，使用相应工具更新
- **世界观加载**：写同人小说时必须首先加载对应的世界观知识库（海贼王/火影/死神），确保 AI 不胡编乱造
- **对话式交互（强制）**：通过对话从用户处逐步获取信息，每次只问1-2个问题，等待用户回答后再问下一个
- **渐进式生成（强制）**：大纲生成遵循"渐进式披露"原则（卷概述→章节概述→详细情节点），每步都必须展示给用户确认
- **因果链推理（强制交互式逐步推理）**：
  - **逐步推理**：每步都等待用户确认或补充
  - **用户可以随时补充**：用户可以主动提供额外的设定或约束
  - **用户可以修改分支**：用户可以对分支提出修改意见，或提供自定义方案
  - **用户可以要求深入分析**：智能体必须展开详细分析
  - **禁止全自动模式**：除非用户明确要求"你直接生成"
- **智能体主导**：核心创作（大纲生成、优化、因果推理）由智能体完成，脚本仅提供结构化支持
- **质量自检**：生成时自动检查8项优化原则
- **蝴蝶效应标注**：生成大纲时，必须标注改变点、连锁反应、蝴蝶效应
- **主角行为逻辑**：生成分支时，遵循"对敌人斩尽杀绝，对路人/无冤无仇者不主动阻挠"的原则
- **分支多样性**：收服不了索隆、收服路飞、收服其他角色，都是可能的分支，不能预设主角一定能成功
- **最小化改动**：优化现有大纲时，只修改问题章节，不要重新设计整个故事线

## 使用示例

### 示例1：生成海贼王同人大纲（交互式逐步推理）

**用户**：帮我生成一个海贼王同人小说大纲，要收服索隆

**Agent 工作流程**：

1. **识别同人类型，加载世界观知识库**（必须首先执行）
   ```
   read_file references/onepiece_knowledge_base.md
   ```
   - 目的：确保 AI 不胡编乱造，严格遵循海贼王原作设定

2. **对话式收集信息（每次只问1-2个问题）**
   - Agent：请告诉我主角的姓名、性格、金手指类型？
   - 用户：李寒，冷静果断，加点系统
   - Agent：主角的起点是什么？（海军/海贼/其他）
   - 用户：从海军三等兵开始
   - Agent：主角的目标是什么？
   - 用户：成为海军元帅
   - Agent：关于收服索隆，您有什么具体想法吗？比如时机、策略？
   - 用户：在谢尔兹镇事件时收服，用情报换取索隆的信任

3. **因果链推理（交互式逐步推理，每步都等待用户反馈）**

   **第1步：分析直接影响**
   - Agent：收服索隆会导致索隆不会加入路飞，路飞失去剑士，战斗力大幅下降
   - Agent：索隆的"世界第一剑豪"目标会受到影响，可能会调整目标
   - Agent：请问您如何看待这个影响？是否接受？
   - 用户：接受，索隆会继续追求世界第一剑豪

   **第2步：分析第1层连锁反应**
   - Agent：路飞失去剑士，在巴拉蒂餐厅对抗克利克时会非常吃力，可能重伤
   - Agent：世界可能会安排其他剑士加入路飞，或者给路飞更强的能力
   - Agent：请问您希望世界如何修正？还是让路飞自己克服？
   - 用户：让世界自动修正，看会出现什么情况

   **第3步：分析第2层连锁反应**
   - Agent：如果路飞在巴拉蒂重伤，可能无法正常前往可可亚西村
   - Agent：阿龙事件可能会推迟，或者娜美被迫独自对抗阿龙
   - Agent：这会影响娜美对路飞的信任，娜美可能不会那么容易信任路飞
   - Agent：请问您希望如何处理？可以让索隆暗中帮助路飞吗？
   - 用户：可以，让索隆偶尔暗中帮助，但不直接暴露身份

   **第4步：分析第3层连锁反应**
   - Agent：长期来看，路飞的团队会变化，战斗力构成也会变化
   - Agent：可能在伟大航路遇到不同的伙伴
   - Agent：您希望路飞的团队如何发展？
   - 用户：正常发展，只是少了索隆

   **第5步：分析世界修正**
   - Agent：世界可能会安排克洛或者其他剑士加入路飞
   - Agent：也可能会给路飞更强的霸气或果实能力
   - Agent：您希望世界如何修正？
   - 用户：让世界自然修正，不干预

4. **生成3个分支（基于用户反馈调整）**
   - Agent：基于以上分析和您的反馈，我生成3个分支供您选择：

   **分支A：保守策略（成功率30%，风险小）**
   - 收服索隆后，让他暗中帮助路飞，不直接暴露身份
   - 路飞团队正常发展，只是少了索隆
   - 世界安排克洛或其他剑士加入路飞
   - 收益：索隆成为您的部下，获得顶尖剑士
   - 风险：路飞战斗力下降，可能影响后续剧情

   **分支B：平衡策略（成功率50%，风险中等）**
   - 收服索隆后，让他偶尔暗中帮助路飞
   - 路飞团队正常发展，在伟大航路遇到新的伙伴
   - 世界给路飞更强的霸气
   - 收益：索隆成为您的部下，路飞继续成长
   - 风险：世界修正可能不可控

   **分支C：激进策略（成功率20%，风险大）**
   - 收服索隆后，让索隆完全脱离路飞
   - 路飞在东海遇到重大困难，被迫快速成长
   - 世界给路飞霸王色霸气觉醒
   - 收益：索隆完全属于您，路飞快速成长
   - 风险：路飞可能夭折，蝴蝶效应严重

5. **用户选择或补充**
   - 用户：我想要分支B，但是索隆不能完全隐藏，要在关键时刻帮助路飞
   - Agent：好的，我调整分支B，加入索隆在关键时刻帮助路飞的设定

6. **根据用户选择生成大纲（渐进式生成，每步都等待用户确认）**
   - 读取大纲结构规范：
     ```
     read_file references/outline_structure.md
     ```
   - 渐进式生成：
     - 第一步：生成卷概述，**展示给用户确认**
     - 用户确认后，第二步：生成章节概述，**展示给用户确认**
     - 用户确认后，第三步：生成详细情节点
   - 质量自检：自动检查8项优化原则

7. **输出结果**
   ```
   write_file 海贼之唯我独尊-大纲.md
   ```
